# Zentral activation

Adaptado de B2B RevOps Skills (MIT, Rutger Katz / Neon Triforce) v1.8.1.

## Cuándo usar

Post-firma / post-piloto convertido a suscripción Zentral. Trigger: "onboarding", "activación", "go-live", "time to value", "PT-PRD-01", "primer KR".

## Definición de activación (evento, no fase)

**Activado =** (1) el **primer flujo contratado** opera en producción con usuarios reales, **y** (2) el **primer KR vinculado** está validado con datos del módulo contratado.

Go-live/configuración/capacitación **no** bastan solos.

## Reglas duras (kit)

- Reloj: **≤15 días hábiles** según PT-PRD-01 (Spaces Zentral company_id=1), salvo cronograma escrito distinto en el alcance.
- Pricing D.3; impl/personalización según alcance acordado. No plazos universales públicos.
- No claim de ahorro/%; baseline y resultados los define el cliente.
- Pedir referido **después** de activación (no antes).
- CRM: Indrox CRM (hitos, stalls, fecha activación). Proceso: PT-PRD-01; venta previa GR-VTA-*.

## Pasos

1. **Recibir context pack** (skill **Indrox handoffs**): dolor, MEDDIC, módulos, usuarios, flujo, criterios, baseline.
2. **Kickoff** — confirmar, no re-entrevistar: "¿qué cambió desde la firma?"; leer en voz alta éxito acordado.
3. **Días 1–5** — accesos, datos de prueba→reales, un solo flujo; perfiles (registra / consulta / aprueba).
4. **Hacia activación** — flujo live; vincular KR a datos del módulo; validar con champion que el indicador se mueve o se lee correctamente.
5. **Documentar en CRM** — fecha activación, evidencia (captura/nota), baseline before/after acordada.
6. **Graduación** — dueño steady-state; próximo check; **pedir 1 referido** con permiso (skill partners).
7. **Expansión** — módulos/usuarios solo tras activación; cross-sell Core si hace falta BuildPro (tag cross-sell).

## Señales de stall (actuar barato)

| Stall | Respuesta |
| :---- | :---- |
| Acceso/datos bloqueados >1 semana | Escalar a sponsor con costo vs fecha crítica |
| Asistencia cae | Conversación con champion: qué cambió |
| Uso flat post-lanzamiento | Encoger al un flujo; no sumar features |

Dos respuestas fallidas → veredicto interno (incl. mal fit); no empujar a "cuenta activa" falsa.

## Qué NO hacer

- Declarar activado por checklist interno sin flujo+KR.
- Prometer "listo en X días" genérico o "todos los KR solos".
- Pedir testimonial/referido sin activación.

## Handoff

- Pack incompleto → **Indrox handoffs**.
- Piloto previo → **Zentral pilot conversion**.
- Referido → **Indrox partner referrals**.
- Deal Core paralelo → **Indrox deal gates**.
