# Indrox deal gates

Adaptado de B2B RevOps Skills (MIT, Rutger Katz / Neon Triforce) v1.8.1.

## Cuándo usar

Revisión de oportunidad, avance de etapa, forecast o duda "¿este deal es real?". Antes de TechBrain, BuildPro, piloto o propuesta de suscripción.

## Reglas duras (kit)

- Metodología: **MEDDIC** (no SPICED por defecto). Discovery con SPIN+MEDDIC.
- Evidencia del comprador > entusiasmo del rep. Escala 1–5 por letra: 1 desconocido → 3 confirmado (cita/log) → 4 cuantificado → 5 validado por tercero/sistema.
- Precios: solo D.3 (módulos USD 39/29/59/29/25; CORE+OKR+IA+3 users; +$10/user; impl por alcance). Core: resultados, no horas; TechBrain pagado/deducible.
- Prohibido: descuentos no autorizados, free trial/piloto gratis, ahorros/% inventados, "software factory", precio por hora.
- CRM: Indrox CRM. Procesos: GR-VTA-01..04, GR-DEM-01/02. Spaces Zentral company_id=1.

## Dimensiones MEDDIC (registrar en CRM)

| Letra | Mínimo para propuesta/piloto |
| :---- | :---- |
| M Métricas | Indicador + **línea base del cliente** (ellos miden; nosotros no inventamos) |
| E Economic buyer | Nombre del firmante; acceso o reunión agendada |
| D Criterios | Qué evaluarán (ajuste rubro, impl, soporte, precio) |
| D Proceso | Pasos, plazos, quién más opina |
| I Pain | Ejemplo reciente + impacto en sus palabras |
| C Champion | Quién empuja adentro |

Regla: ningún campo crítico en 1–2 al pasar a propuesta/piloto. Pregunta zombie: *¿qué se rompe si no hacen nada este trimestre?* Sin respuesta concreta → no es deal.

## Gates por funnel

### Indrox Core
| Transición | Evidencia mínima |
| :---- | :---- |
| Pre-cot → Meet | B.3 ok + rango presupuesto viable |
| Meet → TechBrain | MEDDIC ≥3 en Pain, EB o proceso; interés real |
| TechBrain → BuildPro | Business Case aceptado; métricas/alcance escritos; firmante en loop |
| BuildPro → TechEvolution | Resultado comprometido entregado/aceptado; retainer acordado |

### Zentral
| Transición | Evidencia mínima |
| :---- | :---- |
| Meet → Demo | Proceso real elegido + datos/ejemplo pedidos |
| Demo → Piloto/alcance | Criterios de éxito escritos + baseline cliente |
| Piloto → Suscripción | Criterios cumplidos o decisión explícita; pricing D.3 |
| Activación | Primer flujo live + primer KR validado |

## Pasos semanales

1. Listar deals sobre su gate de evidencia (Indrox CRM).
2. Por deal: **re-calificar** (pregunta + fecha), **bajar etapa**, o **cerrar perdido** con motivo.
3. "Dejarlo y esperar" no es veredicto.

## Qué NO hacer

- Avanzar etapa por "buena vibra" o demo genérica de features.
- Contar pipeline sin next step + fecha.
- Usar piloto gratis como sustituto de calificación.

## Handoff

- Falta discovery → **Indrox discovery**.
- Ciclo lento / zombie → **Indrox deal velocity**.
- Piloto Zentral → **Zentral pilot conversion**.
- Cerrado perdido → **Indrox lost revival**.
