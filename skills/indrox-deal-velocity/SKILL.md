# Indrox deal velocity

Adaptado de B2B RevOps Skills (MIT, Rutger Katz / Neon Triforce) v1.8.1.

## Cuándo usar

Deal estancado, ciclo alargado, "está caliente pero no avanza", o scrub de zombies. Trigger: "velocidad", "zombie", "mutual action plan", "MAP", "no decision".

## Alcance de esta skill

**Solo:** (1) detección de zombies y (2) mutual action plan (MAP).  
No instalar programas de benchmarks ni citar win-rate/% externos **como claim al cliente**.

## Reglas duras (kit)

- Qualify antes de acelerar (skill **Indrox deal gates**). Acelerar un no-fit = perder más rápido.
- Outbound/seguimiento: 4 toques / 14–16 días cuando aplique re-engagement corto.
- No descuentos, free trials ni urgencia falsa para "mover" el deal.
- CRM: Indrox CRM. Procesos GR-VTA-*. Funnel Core o Zentral según marca.

## Detección zombie

Marcar zombie si ocurre **cualquiera**:

- Sin actividad comprador > umbral de etapa (ver **Indrox pipeline desk**).
- Close date empujada ≥2 veces sin cambio de evidencia MEDDIC.
- Single-threaded (solo un contacto) pasado Meet/demo.
- Sin economic buyer identificado al pedir propuesta/piloto.
- "Interés" sin next step fechado mutuo.
- Respuesta a *¿qué se rompe si no actúan este trimestre?* vacía o "creo que…".

Veredicto: re-engage con ángulo nuevo, bajar etapa, o Closed Lost con motivo — no esperanza.

## Mutual Action Plan (MAP)

Documento compartido vendedor↔comprador hacia la decisión.

**Reglas no negociables**

- El comprador posee **>50%** de los pasos.
- Cada paso: dueño nombrado + fecha.
- Se revisa en **cada** llamada; es vivo, no PDF muerto.
- Si el comprador no co-arma el MAP → no hay urgencia real; no forzar.

**Plantilla corta**

1. Objetivo de decisión (suscripción D.3 / TechBrain / BuildPro) y fecha objetivo.
2. Tabla: paso | dueño (ellos/nosotros) | fecha | estado.
3. Criterios de éxito (sus números / baseline).
4. Riesgos y dependencias (datos, accesos, comité).
5. Then-what si se cumplen criterios (path a firma).

Ejemplos de pasos comprador: enviar datos anonimizados; confirmar # usuarios; agendar firmante; revisar propuesta legal; validar baseline del piloto.

## Pasos operativos

1. Confirmar fit B.3 + MEDDIC mínimo (si falla → gates/discovery).
2. Flag zombie en CRM + razón.
3. Proponer MAP en la próxima reunión; guardar link/nota en Indrox CRM.
4. Inspeccionar MAP en deal review; bloquear avance de etapa si fechas del comprador vencen sin update.

## Qué NO hacer

- Usar "el mercado cierra en X días / win rate Y%" como presión al cliente.
- MAP 100% tareas internas Indrox/Zentral.
- Descuento o piloto gratis para destrabar.

## Handoff

- Calificación → **Indrox deal gates** / **Indrox discovery**.
- Piloto → **Zentral pilot conversion**.
- Higiene lista → **Indrox pipeline desk**.
- Perdido → **Indrox lost revival**.
